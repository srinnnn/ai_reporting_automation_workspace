# 日报、周报自动化真实逻辑

## 1. 建设目标

日报和周报不是让 AI 自行计算数字，而是建立一条可追溯的数据生产流水线：

```text
业务原始文件
→ 文件识别与归档
→ 数据校验
→ 标准数据层
→ 确定性指标计算
→ 对比与异常诊断
→ AI生成分析文字
→ 图表与报表组装
→ 质量审核
→ 人工确认
→ 完整交付包与历史版本
```

核心原则：

1. 数字、排名、环比和占比只能由程序计算，不能交给 AI 猜测。
2. AI只负责归纳、解释、形成业务语言和行动建议。
3. AI引用的每个数字必须来自本次计算结果 JSON。
4. 源数据没有的指标必须留空并标记“待补数据”，不能从参考报表复制。
5. 人工成品报表只用于理解结构和展示方式，不能作为当期源数据。
6. 每次运行必须保留源文件、标准数据、计算结果、质检记录和最终版本。

## 2. 统一自动化流水线

### 2.1 事实资料输入

业务把文件放入提交文件夹或从网页上传，至少提供：

- 品牌、平台、统计开始日期、统计结束日期。
- 美团订单商品明细。
- 京东商品分析明细。
- 商品主数据/商品下载表。
- 上一期日报或周报对应的原始数据，系统也可从历史归档自动获取。

按需增加：

- 流量数据：访客数、曝光量、点击量、加购量、支付人数。
- 活动数据：触达人数、核销人数、活动成本、活动目标。
- 库存数据：款号库存、货号库存、门店库存。
- 目标数据：销售目标、订单目标、库存目标、活动目标。

### 2.2 文件识别 Agent

职责：识别文件属于哪个品牌、平台、周期和资料类型。

识别依据：

- 文件名关键词。
- 工作表名称。
- 表头特征。
- 日期范围。
- 品牌和平台字段。

安踏现有文件识别规则：

| 文件 | 识别工作表 | 主要用途 |
|---|---|---|
| 美团商品数据 | 包含订单编号、订单状态、商品实付销售额的明细工作表 | 美团经营、商品、门店、城市、活动、退款、配送分析 |
| 京东商品分析 | `数据`或包含日期、SKUID、实付销售额、商品销量的工作表 | 京东商品、类目、门店覆盖和交易分析 |
| 商品下载 | 包含产品ID、款号、库存、品牌、系列、季节等字段的工作表 | 商品属性、库存、季节、上市时间和选品补充 |

输出：

```json
{
  "brand": "安踏儿童",
  "platform": "美团",
  "report_period": "2026-07-06/2026-07-12",
  "source_type": "order_product_detail",
  "selected_sheet": "商品数据_20260706-20260712_全店数据",
  "confidence": 0.98
}
```

无法识别时进入“待确认”，不得继续计算。

### 2.3 数据校验 Agent

校验分为四层：

1. 文件校验：文件可打开、非空、格式受支持。
2. 结构校验：必填工作表和必填字段存在。
3. 数据校验：日期、金额、数量、订单状态可解析。
4. 业务校验：周期完整、平台正确、品牌正确、合计可对账。

必须拦截：

- 缺少统计日期、商品名称、销售额或销量。
- 美团缺少订单编号或订单状态。
- 同一平台同一周期重复上传且内容不同。
- 金额、数量出现无法解析的文本。
- 日期超出本次统计周期。
- 找不到可识别的订单状态。

只提示、不直接删除：

- 疑似重复订单商品行。
- 未命名商品或款号缺失。
- 商品主数据匹配失败。
- 订单金额与商品金额不一致。
- 商品分类、店铺或城市为空。

输出《数据质量报告》，包含错误数、警告数、缺失字段和处理结论。

### 2.4 标准数据层

原始文件只读保存，清洗结果进入统一标准表：

#### 订单事实表

- 日期、下单时间、完成时间。
- 平台、品牌、店铺ID、店铺名称、城市。
- 订单编号、订单状态、配送状态。
- SKU、款号、商品名称、商品分类。
- 商品销售数量、商品原价销售额、商品实付销售额。
- 平台补贴、商家补贴、退款数量、退款金额。
- 配送时长、是否超时、取消原因。

#### 商品日事实表

- 日期、平台、SKUID、款号、商品名称。
- 类目、大类、商品销量、实付销售额。
- 在售门店数、交易门店数、在售率、交易率。

#### 商品主数据表

- 产品ID、款号、货号、标题、主图。
- 品牌、大类、品类、系列、科技、性别、季节、年份。
- 款号库存、货号库存、近7天销量、近30天销量、上市时间。

字段清洗规则：

- 去除导出文件中的制表符和首尾空格。
- 订单编号、店铺ID、SKU和款号统一按文本保存，防止科学计数法。
- 金额使用 Decimal 计算，保留两位小数。
- 日期统一为 `YYYY-MM-DD`。
- 订单状态使用品牌平台状态映射表，不允许模糊回退到“全部订单”。
- 疑似重复数据先标记，只有满足已确认的唯一键规则才自动去重。

## 3. 日报自动化逻辑

## 3.1 日报定位

日报解决三个问题：

1. 昨天经营结果怎么样。
2. 哪个平台、商品、门店或城市出现异常。
3. 今天优先处理什么。

默认统计周期：昨日 `00:00:00-23:59:59`。

默认比较基准：

- 前一日。
- 上周同一天。
- 当日目标或月度日均目标（仅在业务提供目标时使用）。

## 3.2 日报指标计算引擎

### 美团可真实计算

| 指标 | 计算逻辑 |
|---|---|
| 商品实付销售额 | 完成/有效订单商品行的商品实付销售额求和 |
| 销量 | 完成/有效订单商品销售数量求和 |
| 订单数 | 完成/有效订单编号去重计数 |
| 客单价 | 商品实付销售额 ÷ 订单数 |
| 原价销售额 | 商品原价销售额求和 |
| 折扣金额 | 原价销售额 - 商品实付销售额，结果小于0时标记异常 |
| 平台补贴 | 商品平台补贴金额求和 |
| 商家补贴 | 商品商家补贴金额求和 |
| 退款金额 | 部分退款商品金额求和 |
| 退款数量 | 部分退款商品数量求和 |
| 营业门店数 | 有完成/有效订单的店铺ID去重计数 |
| 成交城市数 | 有完成/有效订单的城市去重计数 |
| 取消订单数 | 取消状态订单编号去重计数 |
| 超时配送订单数 | 是否超时配送为“是”的订单编号去重计数 |
| 催单订单数 | 是否催单为“是”的订单编号去重计数 |

### 京东当前可真实计算

- 商品实付销售额。
- 商品销量。
- 商品、款号、类目排名。
- 在售门店数、交易门店数、商品在售率、商品交易率。

当前京东文件没有订单编号，不能计算京东订单数和客单价。需要补充订单级源表后才能开放。

### 当前不能计算

以下字段在当前安踏源数据中没有稳定来源，必须留空：

- 访客数、曝光量、点击量。
- 支付人数、加购人数。
- 流量转化率、点击率。
- 活动触达人数、核销人数。
- 广告消耗、ROI。

只有业务上传对应流量或活动文件后，才能增加这些指标。

## 3.3 日报异常诊断

规则引擎先判断，AI后解释：

- 销售额、销量、订单数较前一日和上周同日的变化。
- 销售下降是否集中在某平台、类目、商品、门店或城市。
- TOP商品贡献是否过度集中。
- 高销量商品是否低库存。
- 补贴金额、退款金额、取消订单或超时配送是否异常。
- 是否存在零销售门店、突然无数据或周期不完整。

报警阈值不写死在程序中，按品牌配置：

```json
{
  "sales_drop_warning_pct": "待品牌确认",
  "refund_rate_warning_pct": "待品牌确认",
  "timeout_rate_warning_pct": "待品牌确认",
  "low_stock_days": "待品牌确认"
}
```

## 3.4 日报 AI 分析 Agent

AI输入只能是程序计算后的结构化结果、异常明细和已确认业务事件：

```json
{
  "current_day": {},
  "previous_day": {},
  "same_weekday_last_week": {},
  "platform_breakdown": [],
  "top_products": [],
  "store_anomalies": [],
  "data_quality": {}
}
```

AI输出：

- 一句话经营结论。
- 3条以内关键变化。
- 已由数据验证的主要贡献项或拖累项。
- 今日处理建议。
- 待业务确认问题。

AI禁止：

- 编造促销、天气、流量或竞争活动原因。
- 将时间相关性直接描述为因果关系。
- 引用计算结果中不存在的数字。
- 对缺少上期数据的指标生成环比结论。

## 3.5 日报交付包

```text
安踏儿童_经营日报_YYYY-MM-DD/
├─ 01_原始文件/
├─ 02_数据质量报告.xlsx
├─ 03_标准数据.csv
├─ 04_日报指标明细.xlsx
├─ 05_日报看板.html
├─ 06_AI分析初稿.md
├─ 07_人工确认版.xlsx或PDF
└─ manifest.json
```

页面展示：核心指标、日环比/周同日对比、平台结构、TOP商品、异常门店、风险提醒和数据完整度。

## 4. 周报自动化逻辑

## 4.1 周报定位

周报解决四个问题：

1. 本周整体经营表现及与上周的变化。
2. 哪个平台、类目、商品、门店和城市贡献最大。
3. 变化由哪些可验证因素构成。
4. 下周应主推、补货、观察或处理哪些商品和门店。

默认周期：自然周周一至周日。品牌使用其他周定义时写入品牌配置，不允许临时改变。

## 4.2 周报数据准备

系统检查：

- 本周是否包含完整7天。
- 上周是否存在相同口径的完整7天数据。
- 美团和京东日期是否一致。
- 商品主数据是否为统计截止日附近的有效版本。
- 源文件是否已重复处理。

可以直接上传周文件，也可以由7份已审核日报标准数据自动汇总。二者同时存在时进行合计对账，不一致则停止生成结论。

## 4.3 周报指标计算

### 核心指标

- 销售额、销量、订单数、客单价。
- 平台补贴、商家补贴、退款金额。
- 营业门店数、成交城市数。
- 取消订单数、超时配送订单数。
- 本周较上周绝对变化和变化率。

京东订单数和客单价仍需订单级数据，缺失时不参与跨平台订单合计。

### 结构指标

- 平台销售额和销量贡献占比。
- 大类、品类销售额和销量占比。
- 商品TOP10销售额、销量和贡献率。
- 门店TOP/后排、城市TOP/后排。
- 每日销售趋势和周内峰谷。
- TOP商品集中度。

### 商品经营指标

- 本周销量、本周销售额。
- 上周销量、上周销售额。
- 周环比变化。
- 近30天销量。
- 当前库存。
- 库销比或可售天数（仅在库存口径确认后计算）。
- 在售门店数、交易门店数、在售率和交易率。
- 季节、产品季、上市时间、适用人群和系列。

## 4.4 周报诊断 Agent

程序先做贡献拆解：

```text
总销售额变化
→ 平台贡献
→ 类目贡献
→ 商品贡献
→ 门店/城市贡献
→ 补贴、退款和配送风险
→ 未解释残差
```

只有能够量化的贡献项才写成“主要原因”。无法验证的促销、流量、天气、竞品等信息只能写入“待确认假设”。

输出：

```json
{
  "headline_status": "上升/下降/基本持平/不可比较",
  "top_contributors": [],
  "top_drags": [],
  "platform_changes": [],
  "category_changes": [],
  "product_changes": [],
  "store_risks": [],
  "unresolved_movement": []
}
```

## 4.5 下周选品与行动建议

下周选品由规则评分和AI说明共同完成：

程序评分可使用：

- 本周销量和销售额贡献。
- 较上周增长趋势。
- 近30天稳定动销。
- 库存是否可支撑。
- 当前季节和产品季是否匹配。
- 在售门店和交易门店覆盖。
- 是否存在退款、低库存或数据异常风险。

评分权重必须由业务确认并保存版本，AI不能自行决定权重。

AI负责输出：

- 推荐角色：核心主推、场景补充、观察、暂缓。
- 推荐理由：只能引用已计算指标和商品事实。
- 风险提示：低库存、覆盖不足、历史数据不足等。
- 建议场景：只能来自已确认季节、品类、适用场景和活动资料。

## 4.6 周报 AI 撰写 Agent

按固定结构生成初稿：

1. 本周经营摘要。
2. 平台表现。
3. 类目与商品结构。
4. 门店与城市表现。
5. 异常与风险。
6. 下周选品和行动建议。
7. 数据缺口与待确认事项。

每一段结论都绑定数据证据ID，便于页面点击查看来源。

## 4.7 图表与排版 Agent

图表数据由程序生成，AI只决定展示优先级和标题：

- 核心指标卡。
- 本周每日销售趋势。
- 平台贡献图。
- 类目结构图。
- 商品TOP10表。
- 门店/城市表现表。
- 本周与上周变化表。
- 下周选品表。

不从人工周报复制图片、图表或数字。

## 4.8 周报交付包

```text
安踏儿童_经营周报_YYYY-MM-DD_YYYY-MM-DD/
├─ 01_原始文件/
├─ 02_数据质量报告.xlsx
├─ 03_标准数据/
│  ├─ order_fact.csv
│  ├─ product_day_fact.csv
│  └─ product_master.csv
├─ 04_指标计算结果.xlsx
├─ 05_诊断结果.json
├─ 06_周报看板.html
├─ 07_周报初稿.xlsx或PPTX
├─ 08_下周选品.xlsx
├─ 09_人工确认版/
└─ manifest.json
```

## 5. 质量审核 Agent

### 数据审核

- 源文件数量、日期范围和平台是否完整。
- 核心合计是否与源表对账。
- 同一订单是否被重复统计。
- 金额是否使用统一口径。
- 跨期、跨平台比较是否可比。
- 缺少数据时是否正确留空。

### 结论审核

- 每个数字是否存在于计算结果。
- 环比、占比和排名是否可复算。
- “原因”是否有量化证据。
- 是否把待确认假设写成事实。
- 是否引用了参考报表中的旧内容。

审核状态：

- `通过`：可进入人工确认。
- `警告`：允许生成，但必须显示缺口。
- `阻断`：不生成正式报表，只输出数据质量报告。

---

## 6. 人工确认节点

业务不需要重新制作整份报表，只确认以下内容：

1. 数据周期和平台是否正确。
2. 数据质量警告是否可以接受。
3. 业务事件是否确实发生。
4. AI结论是否符合实际情况。
5. 下周选品和行动建议是否执行。

确认后锁定版本，后续修改生成新版本，不覆盖历史文件。

## 7. API与自动化边界

### 不依赖网络API的部分

- 文件识别、清洗、字段映射。
- 金额、销量、订单、占比、排名和环比计算。
- 图表数据生成。
- Excel/CSV/HTML交付。
- 质量规则检查和历史版本管理。

### 建议接入文本大模型API的部分

- 日报经营摘要。
- 周报变化归纳。
- 已验证驱动的业务化表达。
- 行动建议和待确认问题。
- 图表标题和管理层摘要。

### 后续可接入

- 飞书/邮件通知：日报或周报完成后通知审核人。
- 企业登录：统一账号和权限。
- 平台API：自动拉取数据，替代人工下载文件。

模型API不可用时，系统仍完成全部数字计算和报表表格，只把AI文字部分标记为“未生成”，不得使用固定话术冒充AI分析。

## 8. 当前资料缺口与开发前确认项

1. 日报尚无正式安踏日文件样例，目前只有通用模板。
2. 现有日报、周报模板字段相同，周报模板示例行仍写“日报”，需要分别重建。
3. 京东当前没有订单级数据，不能计算订单数、客单价、退款和配送指标。
4. 当前没有稳定的流量、曝光、点击、支付人数和活动核销源文件。
5. 销售额最终采用“商品实付销售额”还是“订单折扣后金额”，需要业务口径负责人确认；系统可以同时保留，但只能指定一个作为主KPI。
6. 美团有效订单状态映射需要业务确认，不能简单使用“包含完成”或在匹配失败时使用全部订单。
7. 疑似重复商品行的唯一键和去重规则需要用真实订单样例确认。
8. 日报异常阈值、周报持平区间、库存风险阈值和选品权重需要业务确认。
9. 最终交付格式需确认：网页看板、Excel、PPTX、PDF或组合。

## 9. 推荐开发顺序

1. 建立日报/周报统一标准数据层和数据质量报告。
2. 完成美团日报确定性指标计算和日报看板。
3. 完成美团+京东周报汇总、周环比和结构分析。
4. 接入商品主数据、库存和下周选品。
5. 接入文本大模型API生成日报/周报初稿。
6. 完成质量审核、人工确认和版本管理。
7. 增加通知、企业登录和自动拉数能力。
